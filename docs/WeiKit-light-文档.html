WeiKit-light 使用文档

WeiKit-light 是一个面向 .NET Framework 4.7.2 的轻量级 WinForms 工具库（OutputType=Library，程序集文件为 WeiKit.dll）。 提供 配置管理、日志、加密解密、程序工具、网络 五组核心模块，并附带零第三方依赖的自绘控件、自定义窗口（消息框 / Toast）、插件管理与 HTTPS API 服务器。

本文档的准确性说明 文中所有类名、方法签名、参数默认值、返回值与行为描述均逐一对照当前源码核对；所有代码示例可直接编译运行。 凡属「源码真实存在但使用上有坑」的行为，一律在 已知陷阱汇总 中明确标注，不做美化。

简介

库的定位是「宿主程序的通用底座」：宿主（你自己的 WinForms 程序或插件宿主）引用 WeiKit.dll 后， 可以直接获得一套可加密落盘的配置系统、带实时窗口和 13 种主题的日志系统、AES 文件加密、 一批进程/路径/哈希工具，以及 HTTP 请求、多线程下载器、上传器和内置 Web 服务器。

把 WeiKit.dll 及其依赖拷贝到宿主输出目录，在宿主项目中添加程序集引用：

<ItemGroup>
  <Reference Include="WeiKit">
    <HintPath>lib\WeiKit.dll</HintPath>
  </Reference>
  <Reference Include="Newtonsoft.Json">
    <HintPath>lib\Newtonsoft.Json.dll</HintPath>
  </Reference>
</ItemGroup>
WebView2 依赖是可选的 只有 Logsinfo 日志窗口使用 Microsoft.Web.WebView2（WebView2 控件）。如果你的程序不用日志查看窗口， 可以不拷贝 Microsoft.Web.WebView2.*.dll；但一旦打开日志窗口就会因缺少程序集抛异常。窗口内部对 WebView2 初始化失败做了兜底：会显示「兼容模式」按钮，可手工切换到内置 WebBrowser 内核渲染（详见 日志查看窗口）。

2. 推荐的启动初始化

宿主 Program.Main 里按下面的顺序初始化，可以把散落在各处的 Console.WriteLine 一并纳入日志系统：

csharp
using System;
using System.Windows.Forms;
using WeiKit;

static class Program
{
    /// <summary>全局日志实例，建议做成静态字段供整个程序复用</summary>
    public static readonly Logs Log = new Logs();

    /// <summary>全局配置实例</summary>
    public static readonly Configs Cfg = new Configs();

    /// <summary>配置文件加密密钥；留空字符串表示明文保存</summary>
    private const string SaveKey = "your-secret-key";

    [STAThread]
    static void Main()
    {
        // ① 接管 Console 输出：此后所有 Console.WriteLine 都会进入日志列表
        Log.RedirectConsoleOut();
        Log.Println("程序启动", "Info");

        // ② 声明配置项（内部名称、类型、默认值、显示名、说明）
        Cfg.Add("General.AutoStart", Configs.ValueType.Bool,   false, "开机自动启动", "随 Windows 一起启动本程序");
        Cfg.Add("General.Theme",     Configs.ValueType.String, "LightClean", "界面主题");
        Cfg.Add("Net.Port",          Configs.ValueType.Long,   5694L, "服务端口");

        // ③ 载入配置；文件不存在时会返回 false，此时用 Save 建立默认文件
        string cfgPath = Tool.GetProgramPath() + @"config\app.json";
        if (!Cfg.Load(cfgPath, SaveKey))
        {
            Log.Println("未找到配置文件，正在写出默认配置。", "Warning");
            if (!Cfg.Save(cfgPath, SaveKey))
                Log.Println("默认配置写出失败！", "Error");
        }

        // ④ 配置变更时同步外部状态（例如注册表自启动）
        Cfg.ConfigChanged += c =>
        {
            bool auto = (bool)c.Read("General.AutoStart");
            Tool.SetAutoStart("MyApp", Application.ExecutablePath, auto);
        };

        Application.Run(new MainForm());
    }
}
已修复：Save 重载不再有「路径被当成密钥」的陷阱

旧版本是 Save(string SaveKey = "") + Save(string path, string SaveKey = "")，两个重载都带默认参数， 导致单参调用 Save("C:\a\b.json") 被解析成「把路径当密钥」，若此时 ConfigFilePath 还是 null 就不抛异常、不报错、什么都不写。

现在的签名把「密钥」和「路径」彻底分开，并返回是否成功：

  • bool Save() —— 写入当前 ConfigFilePath，自动沿用 LastSaveKey（Load 时用的密钥），不会悄悄退化成明文。
  • bool Save(string path) —— 明文写到 path，并把 ConfigFilePath 更新为它。
  • bool Save(string path, string saveKey) —— 写到 path，saveKey 非空则加密。
csharp
cfg.Save();                              // 存回原文件（自动带上原密钥）
cfg.Save(@"C:\a\b.json");                 // 明文另存到指定路径
cfg.Save(@"C:\a\b.json", "your-key");     // 加密另存到指定路径

if (!cfg.Save())                          // 现在能拿到明确的成功/失败
    MessageBox.Show("配置保存失败，详见控制台输出。");

另外：保存时会自动创建目标目录，写盘失败会把原因（含路径）打印到控制台并返回 false，不再静默。

一、配置管理

命名空间 WeiKit · 类 Configs（非静态，每个实例对应一份配置文件）

Configs 是一个「配置项容器 + 文件读写器」。你先把所有配置项用 Add() 声明出来（带上类型和默认值）， 然后从文件 Load() 覆盖值；保存时整份序列化为 JSON。配置项有 4 种类型：

ValueTypeCLR 类型字符串解析窗口中的编辑控件
ValueType.Stringstring原样文本框
ValueType.Longlonglong.Parse数值框（0 位小数）
ValueType.Boolboolbool.ParseSwitch 开关
ValueType.Floatfloatfloat.Parse数值框（2 位小数）

配置文件行为

json
// 明文配置文件（未设置 SaveKey 时）的实际结构 —— 就是 Config 对象的数组
[
  {
    "Name": "General.AutoStart",
    "Text": "开机自动启动",
    "Notes": "随 Windows 一起启动本程序",
    "Type": 0,
    "Value": false,
    "DefaultValue": false,
    "HelpUrl": ""
  }
]

Type 字段是枚举序号：Bool=0、Long=1、Float=2、String=3。

加密载入的自动迁移

当 Load(path, SaveKey) 传入了非空密钥时，载入流程是「先试明文，再试密文」：

  1. 先按明文 JSON 解析。若解析出非空列表，就认为这是一份旧的明文配置，立刻用密钥重新加密保存（自动迁移），并置 IsEncrypted = true。
  2. 明文解析失败（异常）才走 CryptoHelper.LoadDecrypted 解密载入。
加密配置的判定与密钥缺失 IsEncrypted 表示「本次载入时给了密钥」，并不代表文件内容真的是密文。若你用空密钥去 Load 一个加密文件， 会走明文分支，JSON 解析失败 → 进入外层 catch → 返回 false 且 IsEffective = false，不会抛异常。 这也是 配置管理窗口「保存」按钮那个奇怪逻辑的成因。

Configs API

属性与字段

string ConfigFilePath { get; }
当前配置文件路径。仅私有 setter：由 Load(path) 或 Save(path, ...) 写入。初始为 null。
bool IsEffective { get; }
最近一次 Load 是否成功。文件不存在、解析失败、解密失败、数据为空时均为 false。
bool IsEncrypted { get; }
本次载入是否使用了密钥（见上方警告框）。
List<Config> configs
配置项列表，公开字段，可直接遍历（配置管理窗口正是用 Configs.configs 建树）。
event ConfigsChangedEventHandler ConfigChanged
配置变更事件。委托签名：void ConfigsChangedEventHandler(Configs configs)。
触发时机：WriteValue / WriteStrValue 成功、Add 成功、Remove 成功、Reset 成功、ResetAll、Load 成功。
注意：直接修改 configs[i].Value 或 GetConfig(name).Value 不会触发该事件（配置管理窗口就是这样改值的）。
event EventHandler ConfigManagFormClosed
配置管理窗口关闭时触发（由 ShowConfigManagForm 打开的那个窗口）。

配置项对象 Configs.Config

成员类型说明
Namestring内部名称，读写时的唯一键
Textstring显示名称；Add 时传空则取 Name
Notesstring解释信息，默认 "暂无解释信息。"

方法

bool Add(string name, ValueType type = ValueType.String, object value = null, string text = "", string notes = "暂无解释信息。", object defaultvalue = null, string heplurl = "")
新建一个配置项。同名已存在则返回 false 并打印一行提示到控制台。
参数：heplurl 是源码里的拼写（不是 helpurl），建议用具名实参调用以免顺序出错。
返回值：成功 true；同名冲突 false。
副作用：成功时触发 ConfigChanged。
Config GetConfig(string name)
按内部名称取配置项对象；未找到返回 null（configs 为 null 时也返回 null）。
bool IsHave(string name)
是否存在指定名称的配置项。等价于 GetConfig(name) != null。
int GetConfigIndex(string name)
配置项在 configs 中的索引；未找到返回 -1。
string[] GetConfigNameList()
返回所有配置项的内部名称数组；configs 为 null 或空时返回 null（不是空数组，调用方需判空）。
object Read(string name)
读取配置值。返回 object，需要自行强制转换；未找到时打印提示并返回 null。
注意：Read 不做类型转换。布尔项要写 (bool)cfg.Read("X")，整型项是 long 而非 int：(long)cfg.Read("X")。
bool WriteValue(string name, object value)
直接写入值（不做类型校验，传错类型会在后续读取或保存后反序列化时暴露）。未找到配置项返回 false。
bool WriteStrValue(string name, string value)
按配置项声明的类型把字符串解析后写入，适合从文本框/命令行接收输入的场景。
返回：解析失败或配置项不存在返回 false，且原值保持不变（不会污染配置）。
数值解析：Long/Float 使用不区分区域性的 InvariantCulture；Long 同时接受 "3" 与 "3.0" 两种写法。
bool Remove(string name)
删除配置项。成功返回 true 并触发 ConfigChanged；不存在返回 false。
bool Reset(string name)
把单项恢复为 DefaultValue。成功触发 ConfigChanged。
void ResetAll()
把所有配置项恢复为 DefaultValue，触发一次 ConfigChanged。不落盘，需自行 Save。
bool Load(string path, string SaveKey = "")
从 path 载入配置。SaveKey 为空走明文，非空走「先明文后密文」的自动迁移流程。
返回值：成功 true；文件不存在 / 解析失败 / 数据为空 / 解密失败均为 false。
失败时不会抛出异常，所有错误都以 Console.WriteLine 形式输出（配合 Logs.RedirectConsoleOut() 可进入日志）。
成功时：覆盖 configs、记录 ConfigFilePath 与 LastSaveKey、IsEffective = true、触发 ConfigChanged。
检测到旧明文配置时（传了密钥但文件是明文 JSON）：自动重新加密写回，并置 IsEncrypted = true。
bool Save()
保存到当前 ConfigFilePath，自动沿用 LastSaveKey（即最近一次 Load/Save 用过的密钥）。
返回：成功 true；ConfigFilePath 为 null（从未载入/保存过）或写盘失败时返回 false，并打印原因。
保存会自动创建目标目录；加密配置不会因为走这个无参重载而变成明文。
bool Save(string path)
明文保存到指定路径，并把 ConfigFilePath 更新为该路径、LastSaveKey 清空。
旧版本这里容易被误解析成「密钥」，现已彻底分离，传入路径就是路径。
bool Save(string path, string saveKey)
保存到指定路径；saveKey 非空时调用 CryptoHelper.SaveEncrypted 加密写入，并记录到 LastSaveKey。
返回：写盘结果。失败时打印 配置数据保存失败->路径：原因。
string LastSaveKey { get; }
最近一次载入/保存使用的加密密钥（空字符串表示明文）。由 Load / Save 自动记录，无需手动维护。
bool OutSave(string path)
导出为明文 JSON（无视加密设置，永远明文），不修改 ConfigFilePath。对应配置窗口「导出配置」菜单。
返回：是否导出成功。会自动创建目标目录，失败时打印原因（已修复：旧版本返回 void 且失败静默）。
bool InputData(string path)
从文件导入配置：按 Name 合并 —— 同名项整条覆盖，新名项追加。
返回：是否成功导入。
导入成功后会触发一次 ConfigChanged（已修复：旧版本不触发），但仍不会自动落盘，需要保存请自行调用 Save()。
bool Copy(string name, Configs Toconfigs)
把本实例中名为 name 的配置项复制到另一个 Configs 实例（整条复制，含 Notes/Text/Type/Value/DefaultValue/HelpUrl）。
返回：是否复制成功（源中没有该项目返回 false）。
参数校验：Toconfigs 为 null 时抛 ArgumentNullException（已修复：旧版本会新建临时对象、静默丢弃结果）。
int CopyAll(Configs Toconfigs)
逐个调用 Copy 复制全部配置项。
返回：成功复制的项数。Toconfigs 为 null 时抛 ArgumentNullException。
Configs SeparationConfigs(string[] names)
按名称列表拆分出一个新的 Configs：把 names 中存在的配置项复制到新对象，不存在的项被忽略。
插件系统（ModuleManager）用它从宿主配置里为插件装配独立的配置子对象。
bool MergeConfigs(Configs otherConfigs)

控制台重定向 RedirectConsoleOut()

TextWriter RedirectConsoleOut()
把 Console.Out 替换为内部 CustomTextWriter：此后的 Console.Write / WriteLine 全部变成类型为 "Console" 的日志。随后打印两行库信息。
返回值：重定向之前的原始 TextWriter，可传给 Logs.RestoreConsoleOut 恢复。
为什么要用它：Configs、WebServer、HttpLink 等模块的错误提示都走 Console.WriteLine， 重定向后这些信息才进入日志系统，否则只会出现在控制台窗口里。
void RestoreConsoleOut(TextWriter original = null) static
恢复 Console 的标准输出。original 传 RedirectConsoleOut() 的返回值； 传 null 时恢复为一个写向标准输出的新 StreamWriter。
已修复：重定向可逆 + 内置重入保护
  • 可逆：RedirectConsoleOut() 现在返回原始输出流，配合 Logs.RestoreConsoleOut(original) 即可还原， 不再需要自己保存 Console.Out。
  • 递归已受保护：Println 与 CustomTextWriter 都带重入保护。 即使在 LogAddEvent 回调里调用 Console.WriteLine，递归产生的日志也会被直接丢弃， 不会再无限递归导致栈溢出（本库的示例程序开发过程中真实踩过这个坑）。
  • 顺带修复：使用 Println 直接打印时也会走同一套保护，与是否经过 Console 无关。

仍建议：日志事件回调里优先写文件或更新 UI，不要写 Console——那样写的内容会被保护机制丢弃。

剩下一个要注意的点 Write(char) 仍是逐字符调用 Println。若某处代码逐字符输出，日志会被切碎成大量单字符条目。 这是设计取舍（保持 TextWriter 语义），调用库时无需处理。

三、加密解密

命名空间 WeiKit · 静态类 CryptoHelper

提供「对象 → JSON → AES 加密 → 文件」以及反向操作的一对泛型方法。Configs 的加密保存/载入就是调用它。

文件格式

待加密对象的 JSON（UTF-8 文本） │ ├─ ① 生成 32 字节随机盐（RandomNumberGenerator） │ ├─ ② Rfc2898DeriveBytes(password, salt, 10000, SHA256) │ ├─ Key = 前 32 字节（aesAlg.KeySize / 8 = 256 bit） │ └─ IV = 后 16 字节（aesAlg.BlockSize / 8 = 128 bit） │ ├─ ③ AES 加密（Aes.Create() 默认 CBC + PKCS7 填充） │ └─ ④ 落盘文件 = [32 字节盐] + [密文]
读取端按固定 32 字节切分盐值 LoadDecrypted 硬编码 saltLength = 32：文件小于 32 字节直接抛 InvalidOperationException("文件数据损坏，无法提取盐值。")。因此这个格式与写入端一一对应，不能读别处生成的密文。

CryptoHelper API

void SaveEncrypted<T>(string filePath, T obj, string password) where T : class
把对象序列化为 JSON 并加密写入文件。目录必须已存在（不会自动创建）。
异常：
· ArgumentException —— filePath 为空或全空白（消息「文件路径不能为空或空白。」）／password 为空或全空白
· ArgumentNullException —— obj 为 null
· DirectoryNotFoundException —— 目标目录不存在
· JsonSerializationException —— 对象无法序列化（如含循环引用）
T LoadDecrypted<T>(string filePath, string password) where T : class
读取文件、解密、反序列化为 T。密码错误时 AES 解密抛 CryptographicException（填充无效），不会返回 null。
异常：ArgumentException（路径/密码为空）、FileNotFoundException（文件不存在）、 InvalidOperationException（文件不足 32 字节）、CryptographicException（密码错误或数据被篡改）、 JsonSerializationException（明文不是合法 JSON）。
csharp
// 定义一个可序列化的授权信息类
public class License
{
    public string MachineCode { get; set; }
    public string Owner       { get; set; }
    public DateTime ExpireAt  { get; set; }
    public int Level          { get; set; }
}

string dir = Tool.GetProgramPath() + @"data";
Directory.CreateDirectory(dir);                       // 目录要自己建

// 写入

{
    MachineCode = ProgTool.GenerateMachineCode(),
    Owner       = "Tiangong",
    ExpireAt    = DateTime.Now.AddYears(1),
    Level       = 3
};
CryptoHelper.SaveEncrypted(file, lic, "pwd-2026");

// 读取（密码错误会抛 CryptographicException，务必捕获）

{
    License back = CryptoHelper.LoadDecrypted<License>(file, "pwd-2026");
    if (back.MachineCode != ProgTool.GenerateMachineCode())
        MessageBox.Show("授权与本机不匹配");
    else if (back.ExpireAt < DateTime.Now)
        MessageBox.Show("授权已过期");
}
catch (System.Security.Cryptography.CryptographicException)
{
    MessageBox.Show("授权文件解密失败（密码错误或文件损坏）");
}
catch (System.IO.FileNotFoundException)
{
    MessageBox.Show("未找到授权文件");
}
安全提示
  • 密钥派生 10000 次 SHA256 迭代、CBC + PKCS7，没有 HMAC 完整性校验——密文可被篡改（虽多半会在填充校验时失败）。适合保护本地配置文件，不适合对抗主动攻击者。
  • 密码硬编码在客户端时，安全性等同于混淆。若确实需要防盗版，应把校验放到服务端。
  • RC2/DES 之类弱算法在库中没有使用；SakuraFrpcAPI 里会全局降低 ServicePointManager.SecurityProtocol（见 该节），与本节无关。

DownTool 下载器

嵌套类 HttpLink.DownTool · 实现 IDisposable

自动在单线程与多线程之间选择，支持进度回调、取消与失败原因查询。

csharp
using (var down = new HttpLink.DownTool())
{
    // 进度 / 完成回调（在后台线程触发，更新 UI 需 Invoke）
    down.ProgressChanged += p =>
        label1.SafeInvoke(() => label1.Text = $"{p:F1}%");

    down.DownloadCompleted += (ok, reason) =>
    {
        if (ok) MessageBox.Show("下载完成");
        else   MessageBox.Show("下载失败：" + reason);
    };

    // 开始下载（Auto = 大于 100MB 自动多线程）
    down.StartDownload(
        "https://example.com/big.iso",
        @"C:\demo\big.iso",
        HttpLink.DownTool.DownMode.Auto);

    // 轮询状态
    while (down.IsDownloading)
    {
        Console.WriteLine($"{down.DownloadProgress:F1}%  {down.Speed / 1024} KB/s  剩余 {down.RemainSize} B");
        Thread.Sleep(500);
    }

    // down.CancelDownload();   // 需要时取消
}   // Dispose 会取消并在可能的情况下清理 .partN 临时文件

下载模式选择逻辑

传入模式实际行为
DownMode.Auto（默认）文件 > 100 MB → 多线程；否则单线程
DownMode.MultiThread要求文件 > 1 MB，否则仍退化为单线程
DownMode.SingleThread始终单线程流式写入

多线程策略

  • 线程数 = clamp(TotalSize / 20MB, 4, 12)，再与 ceil(TotalSize / 1MB) 取小。
  • 每个分片用 HttpWebRequest.AddRange 请求 [start,end]，写入 {savePath}.part{i}，单分片最多重试 3 次（退避 1s/2s/3s）。
  • 监控线程每 500 ms 汇总各分片进度并计算速度；全部分片结束后顺序合并并删除分片文件。
DownTool 的硬性前提与已知缺陷
  • 必须支持 HEAD 且返回 Content-Length：StartDownload 先用 HEAD 取总大小，取不到（返回 0 或异常）会直接判失败并回调 DownloadCompleted(false, "获取目标文件大小失败…")。分块下载的服务器、需鉴权的链接都会失败。
  • 多线程依赖服务端支持 Range：若服务器忽略 Range 头，每个分片都会拿到完整文件，合并结果损坏。文件 > 1 MB 时， 对不确定支持 Range 的站点请显式用 DownMode.SingleThread。
  • 极小文件不要用多线程：线程数计算可能与总大小不匹配，partSize = TotalSize / numberOfThreads 存在除零风险（numberOfThreads 为 0 时）。
  • 回调在后台线程：ProgressChanged 与 DownloadCompleted 都不在 UI 线程，更新界面必须 Invoke/SafeInvoke。
  • 取消后可能残留分片：Dispose 会尝试删除 .part0..part99，但取消发生在合并阶段时结果文件可能是不完整的。

  1. 取 request.RawUrl；若为 "/" 则改写成 "/index.html"。
  2. 先查软页面（pages 列表）命中则直接返回该内容，Content-Type: text/html; charset=utf-8。
  3. 未命中则拼物理路径 RootPath + RawUrl（把 / 换成 \，再合并重复反斜杠）并 URL 解码；文件存在则按扩展名给 Content-Type 返回（html/css/js/png/jpg/jpeg/gif，其它为 application/octet-stream）。
  4. 都不存在则返回内置 404 页面（把请求路径嵌入页面正文）。
  5. 每次响应结束都会触发 AccessEvent（参数是命中文件路径，404 时是拼出的路径）。
LANS 模式与权限 ServerStart(port, root, LANS: true) 会把监听前缀改成 http://*:{port}/（并用本机第一个 IPv4 作为 Prefix）。 监听非 localhost 前缀时 Windows HTTP.sys 需要 URL ACL 或管理员权限，否则 listener.Start() 抛 HttpListenerException(5, 拒绝访问)。库只捕获异常并写入日志，不会自动提权。 先执行 netsh http add urlacl url=http://*:5694/ user=%USERNAME%，或让程序以管理员运行（可用 ProgTool.RunAsAdmin()）。
停止机制 StopServer() 置退出标志 → listener.Stop() → 再向 http://localhost:{port}/__shutdown_signal__ 发一个带 3 秒超时的 GET 请求，用来唤醒阻塞中的 GetContext()。线程随后在 HttpListenerException(995/1236) 或 ObjectDisposedException 处分支正常退出。
已修复：方法现在会 Join(5000) 等待线程真正退出——退出成功则把 SeverThread 置空， 超时则写入一条警告。停止完成后再读 ServerStarted 就是准确值了。
已修复：路径穿越防护 物理路径经过 IsPathInsideRoot 校验：解析为绝对路径后必须仍在站点根目录内，否则直接返回 403 Forbidden 并写入一条安全日志。请求 URL 也会先去掉查询字符串再做 UrlDecode， 避免 ?a=1 混进文件名。校验逻辑同时以静态方法暴露： WebServer.IsPathInside(root, target)，便于在业务代码里复用。
另一个仍需注意的点 软页面与静态文件同路径时软页面优先，且软页面内容一律按 text/html; charset=utf-8 返回—— 返回 JSON 也能用，但 Content-Type 不准确，前端 fetch().json() 需注意。

附录 D · 常见问题

日志窗口打不开 / 一片空白？

先确认宿主输出目录里有 Microsoft.Web.WebView2.Core.dll、Microsoft.Web.WebView2.WinForms.dll 与 WebView2Loader.dll，并且系统装了 WebView2 Runtime。都齐了还空白，就点窗口里的「兼容模式」按钮切到内置浏览器内核。

配置读出来是 null？

三种可能：① 名字写错（Read 找不到时返回 null 且只打印一行控制台提示）； ② 忘记先 Add 声明——Load 会用文件内容整体替换 configs，所以文件里没有的项在载入后就消失了； 正确做法是「先 Add 默认项，再 Load 覆盖值」。 ③ 加密文件用空密钥载入，IsEffective 为 false，configs 保持你 Add 时的默认值。

为什么保存后配置项少了？

Save 写出的是当前 configs 列表。如果 Load 一个「只包含部分配置项」的文件， 列表会被整体替换成文件里的内容，未在文件中的项就没了。同理，Load 之后再 Add 新项并保存是安全的（新项会写进文件）。

当前版本可自行判断保存是否成功：Save() / Save(path) / Save(path, key) 都返回 bool， 失败时会把「路径 + 原因」打印到控制台（配合 RedirectConsoleOut 可在日志窗口看到）。 因此「配置文件没更新」这类问题不再需要靠猜。

多线程下载的文件损坏 / 大小不对？

服务端不支持 Range 时，每个分片都会下到完整文件，合并后必然损坏。 用 DownMode.SingleThread 重试可确认；若单线程正常、多线程损坏，就是这个原因。

下载直接失败，FailReason 说「获取目标文件大小失败」？

StartDownload 依赖 HEAD 请求返回 Content-Length。链接需要鉴权、服务器禁用 HEAD、 或响应是分块传输（chunked）时都会失败。可先用浏览器或 HttpLink.GetTask 验证链接可达，再确认服务端支持 HEAD。

WebServer 启动报「拒绝访问」？

监听 http://*:port/ 需要 URL ACL。用管理员命令行执行 netsh http add urlacl url=http://*:5694/ user=%USERNAME%，或让程序提权运行（ProgTool.RunAsAdmin()）。 只用本机访问时保持 LANS: false（仅 localhost）不需要任何额外权限。

加密配置的密码改了，旧文件读不出来？

AES 密钥由密码派生，密码变了就解不开（抛 CryptographicException）。库没有密钥轮换机制， 需要平滑迁移请自行实现「用旧密码读出 → 用新密码写回」。

把库打包给别人时要注意什么？

  • 必须一起分发：WeiKit.dll、Newtonsoft.Json.dll。
  • 使用日志窗口还需：三个 WebView2 程序集 + WebView2Loader.dll（或依赖目标机已装 Runtime；WinForms 托管程序集仍需随包分发）。
  • 使用机器码功能需确认目标机 WMI 服务正常（极少精简系统会禁用）。
  • 宿主项目的目标框架需为 .NET Framework 4.7.2 或更高兼容版本。
